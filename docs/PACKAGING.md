# Упаковка

Исходник пакета содержит `yam.yaml` и файлы для установки.

```yaml
name: example/hello
version: 1.0.0
license: MIT
description: Пример пакета
targets: [yandexmicro]
files:
  bin/hello: target/$YAM_TRIPLE/release/hello
  share/example.hello/: share/example.hello/
```

Имя имеет вид `<пространство>/<имя>`. Для нативного кода укажите конкретную
платформу; `any` допустим только для независимых от архитектуры файлов (YAM
это не проверяет). В манифест всё равно пишется архитектура профиля сборки,
и установка требует её совпадения, поэтому пакет `any` ставится только на
платформы той же архитектуры.

Соберите программу и создайте архив:

```sh
cargo build --release --target aarch64-unknown-linux-musl
yam-publish --platform yandexmicro pack --source . --output hello.yampkg
```

`.yampkg` — архив `tar.zst`. YAM сам создаёт `MANIFEST.yaml` и хеши файлов.
Не редактируйте архив вручную.

Проверьте пакет в отдельном каталоге:

```sh
yam --platform yandexmicro --root ./test-root install --yes hello.yampkg
yam --platform yandexmicro --root ./test-root doctor
```

`repair` восстанавливает только ссылки, известные YAM; чужие файлы он не
заменяет. Если по пути ссылки уже лежит обычный файл или чужой симлинк
(не в `pkgs/` этого же пакета), установка и `repair` отказываются его
трогать и называют, что там лежит.

Для пакетов не из `yam/` каждый путь в `share/` должен содержать компонент
`<namespace>.<name>` или начинающийся с `<namespace>.`, например
`share/host/plugins/nikita.soloist/main.lua`. Пакеты `yam/` от
правила освобождены; `bin/` правило не касается.

Архив ограничен по размеру и числу записей: не более 64 МиБ в сжатом виде,
256 МиБ в распакованном, 64 МиБ на файл, 10000 записей. Первой записью
архива должен быть `MANIFEST.yaml`. Лимиты проверяются по фактически
прочитанным байтам, а не по заголовку tar.

На время установки, удаления и `repair` YAM держит эксклюзивный `flock`
на `$YAM_RUN/yam.lock`; при занятом локе команда сразу завершается
ошибкой. Авторам хостов, читающим общие каталоги YAM, достаточно взять
разделяемый лок на тот же файл.

## Зависимости

```yaml
depends: [yam/audio-base]
recommends: [yam/webpanel]
conflicts: [old/player]
replaces: [old/player]
```

`replaces` нужен, если пакет намеренно заменяет файлы другого пакета. Без него
коллизия путей приведёт к ошибке. Пример взаимоисключающих провайдеров:

```yaml
provides:  [spotify-connect]
conflicts: [spotify-connect]
replaces:  [spotify-connect]
```

При установке такого пакета, если `spotify-connect` уже предоставляет
другой установленный пакет, тот удаляется целиком (требуется `--yes`), а
зависимости по `spotify-connect` остаются удовлетворены новым пакетом.
Удаление идёт под тем же локом, но отдельно после установки нового пакета, а
не в одной транзакции: если оно упадёт, новый пакет останется установленным
вместе с частью заменяемых. Зависимость по полному имени заменённого
пакета сохранить так не получится — установка будет отклонена.

Entware не включается в пакет:

```yaml
entware:
  packages: [ffmpeg]
```

Интерактивного подтверждения нет: без `--yes` установка такого пакета
завершается ошибкой, с `--yes` YAM сразу вызывает `opkg install` для этого
списка. Если Entware не установлен (`/opt/bin/opkg` из профиля отсутствует),
установка отклоняется.

Сервис можно описать без shell-команды:

```yaml
services:
  worker:
    exec: [bin/worker, --config, "${YAM_ETC}/worker.toml"]
    restart: on-failure
    after: [network]
    env:
      RUST_LOG: info
    oneshot: false
```

Поля сервиса: `exec` (обязательно; первый элемент — путь файла из пакета),
`restart` (`never` по умолчанию, `on-failure`, `always`), `after`, `env`
(ключи `A-Z0-9_`), `oneshot`. Имя сервиса — `a-z`, `0-9`, `-`.

YAM только сохраняет декларации при установке; супервизора, запускающего
или перезапускающего сервисы, в нём нет. Запуск остаётся за хостом.
Не добавляйте в пакет init-скрипты systemd, OpenRC или BusyBox.

Посмотреть сохранённые декларации можно командой `yam service list`.

## Остальные поля `yam.yaml`

Обязательны `name`, `version`, `license`, `description`, `targets`, `files`.
Необязательны: `homepage`, `depends`, `recommends`, `enhances`, `provides`,
`conflicts`, `replaces`, `permissions`, `entware`, `services`, `postinstall`. Неизвестные
поля отвергаются.

## Postinstall

После успешной распаковки и создания ссылок пакет может выполнить один
`postinstall` hook. Это массив аргументов, не shell-строка: первый элемент
обязательно должен ссылаться на файл пакета в `bin/`.

```yaml
files:
  bin/postinstall: scripts/postinstall.sh
postinstall: [bin/postinstall, --configure]
```

Hook запускается от root с таймаутом 60 секунд. Он получает `YAM_ROOT`,
`YAM_PKG`, `YAM_ETC`, `YAM_VAR`, `YAM_RUN` и `YAM_PLATFORM`; рабочий каталог —
директория установленной версии пакета. При ненулевом коде завершения или
таймауте YAM откатывает установку и её ссылки. Скрипт должен быть идемпотентным;
изменения вне файлового состояния пакета (например, в `YAM_VAR`) не могут быть
автоматически отменены.
